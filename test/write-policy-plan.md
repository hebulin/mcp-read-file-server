# 2.1.0 通用写入状态验收

本次任务：修复原始明文文件经MCP编辑后被加密而IDEA不可读的问题，策略不能按SCSS特判。以下计划在执行测试前保存。

1. 模拟Node可读明文、外部进程可见密文，检查已有明文文件在任意后缀、大小写后缀、无后缀、点文件名下仍保持明文。
2. 覆盖编辑、覆盖写、追加（BOM/CRLF）、新建、二进制复制、移动、目录逐文件操作；新目标参考源文件，覆盖目标参考目标原状态。
3. 同后缀的明文与受保护文件分别观察，不缓存文件状态；受保护状态变为明文时中止。
4. 保持显式策略及持久人工标注优先级；预览不写入；相同内容返回实际策略及校验范围。
5. 注入基线读取失败、读取期间变化、安全中转全失败、最终路径加密，验证不回退直写及失败回滚/源保留。
6. 验证Windows无外部读取器时auto失败，普通非Windows无加密观察时维持unknown告警；通过真实stdio检查此行为。
7. 运行全部已有回归、语法/LF检查和依赖审计，检查2.1.0版本及README与v1.0真实标签的差异描述。

测试样本及profile隔离在项目 `.agent-tmp/` 下，结束后清理；不读取或修改用户真实加密策略。模拟结果不替代真实TSD驱动验收：加密电脑仍需用原始明文文件与原受保护文件分别检查IDEA读取结果。
